fsv User Guide

Explore a filesystem as an interactive 3D map or a circular tree. This guide covers the main window, navigation, coloring, settings, and command-line options.

Getting started

fsv scans the directory you choose and builds a 3D view of its folders and files. A large tree may take time to scan and arrange. The application opens in MapV unless you choose TreeV with the Vis menu or --treev.

To change the scanned root while the app is open, use File → Change root… or the header's Set as root button.

Navigation

Select

Left-click a node in the 3D view to select it. Selecting in the directory tree or file list also selects the matching node in the 3D view.

Look at / go to

Double-click a node in the 3D view, directory tree, or file list to move the camera to it. The Look at action in the selected-object toolbar also moves the camera.

Rotate

Hold Ctrl and left-drag over the 3D view to revolve the camera.

Tilt

Middle-drag over the 3D view to tilt the camera.

Zoom

Use the mouse wheel over the 3D view to dolly in and out.

Context actions

Right-click a node for actions such as Expand, Collapse, Look at, and Properties. Available actions depend on the node.

The horizontal and vertical scrollbars can also move the view. Use Navigation → Previous view to return to the previous camera target, or Look at filesystem root to go to the root.

Views

MapV

Shows the filesystem as a rectangular map. Folders contain their descendants; expanding a folder opens its region. This is the default view.

TreeV

Shows the hierarchy as a circular, tiered tree. Folder platforms can be expanded or collapsed. Very large trees can take longer to arrange and draw.

Overview

The header's Overview toggle switches to a bird's-eye view. Toggle it again to return to the ordinary camera view.

Colors and legend

Choose the coloring mode from the header's color menu or the hamburger menu's Colors menu. Colors → Setup… configures colors, timestamps, and wildcard groups. The floating legend updates to describe the active mode; toggle it with Settings → Show color legend or close it with its × button.

  • By node type: each filesystem node type uses its configured color.
  • By timestamp: files use a spectrum based on access, modification, or attribute-change time. The selected oldest/newest range controls the endpoints. Directories keep their node-type colors.
  • By wildcards: files use the first matching configured wildcard group, or the default color if none matches. Directories keep their node-type colors.
  • By file type: files use semantic categories (source code, media, archives, system/executable, documents, or other). Directories use a muted color based on the dominant category in their contents.

Search

Type part of a file or folder name in the header search field and press Enter. Search is case-insensitive and matches names anywhere in the scanned tree. Press Enter again to cycle through matches. The matching item becomes selected and the camera moves to it. The status bar reports the current match and total count. Search is limited to the currently scanned root; change root to search another part of the filesystem.

Command line

fsv [options] [ROOTDIR]
OptionDescription
ROOTDIRDirectory to scan; defaults to the current working directory.
--mapvStart in MapV (default).
--treevStart in TreeV.
--backend auto|x11|waylandSelect GTK's display backend before GTK starts. auto uses GTK's normal session-based choice. On a Wayland desktop, X11 generally means XWayland. This does not select a different 3D renderer.
--cachedir DIRReserved for caching; currently prints a notice and has no caching effect.
--nocacheReserved for caching; currently has no effect.
--helpPrint the command-line help and exit.

FSV_BACKEND=auto|x11|wayland selects the backend when no valid --backend option overrides it. GTK chooses the default when no override is set. Backend performance varies by system and graphics driver.

fsv ~/Documents
fsv --treev --backend wayland ~
FSV_BACKEND=x11 fsv ~

Performance measurements: use the same root, view, camera movement, and settings when comparing display backends. fsv's FPS display counts render callbacks; the optional profiler measures application CPU/GPU work, not frames actually presented by the compositor.
